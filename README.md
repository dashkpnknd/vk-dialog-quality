# VK Квалы — бот для оценки рекламных диалогов

Программа работает на сервере. Она читает диалоги сообществ VK, отличает самостоятельные ответы клиентов от нажатий кнопок бота, считает долю «квалов» по числовым рекламным меткам, записывает подробности в Google-таблицу и отправляет краткий отчёт в Telegram.

## Команды бота

- `/report` — сводка за 30 дней по магазинам и полный CSV-файл по всем рекламным ID в Telegram.
- `/today` — сводка за сегодня.
- `/group ID` — результаты по рекламным ID одного магазина.
- `/groups` — подключённые магазины.
- `/sheet` — ссылка на Google-таблицу.
- `/sync` — запустить сбор вручную.
- `/status` — состояние сбора.

Бот открыт всем пользователям в личном чате. Любой человек, нашедший его публичное имя, сможет просматривать отчёт и добавлять проекты или VK-группы. Это выбранный владельцем режим доступа. Ежедневный сбор и отправка отчёта подписавшимся через `/start` запускаются после 03:00 по Москве.

## Предварительные правила подсчёта

1. Если в истории человека появляется новая числовая рекламная метка, создаётся новое обращение. Старое остаётся в отчёте. Повторяющиеся сообщения с той же меткой относятся к одному обращению.
2. Самостоятельный ответ может прийти в любой день после обращения: при следующем сборе прежний результат пересчитается.
3. Самостоятельный текст и вложения, включая фото, видео и голосовые, считаются ответом. Нажатия кнопок не считаются.
4. Когда текст совпал с кнопкой, но VK не передал `payload`, диалог попадает в «Проверить вручную».

Если в старом диалоге появился новый ответ, но VK не показал новой рекламной метки, бот не может приписать этот ответ новой кампании. Спорные случаи видны отдельно.

## Что ещё требуется для настоящего запуска

- Токен Telegram-бота от BotFather.
- Токены сообществ VK с доступом к сообщениям и числовые ID сообществ.
- Google-таблица и сервисный аккаунт Google с правом её редактирования.
- Проверка на одном реальном диалоге: совпадают ли поля VK API `ref`/`ref_source` с рекламной меткой в интерфейсе и как API передаёт нажатия кнопок.

Эти данные **не входят в репозиторий**. Сообщения клиентов в базе не сохраняются; хранятся только ID собеседника, метка и результат подсчёта.

## Установка на сервере

Требуется Docker с Compose. В папке проекта:

```bash
cp .env.example .env
mkdir -p data secrets
docker compose up -d --build
```

В `.env` заполните `TELEGRAM_BOT_TOKEN`. Проекты и токены групп можно добавить через кнопки «➕ Проект» и «➕ Группа» в Telegram. Сообщение с токеном бот попытается удалить сразу после получения. Telegram уже получает этот токен до удаления сообщения; используйте этот способ только если такое хранение приемлемо. Альтернативно добавляйте токены через консоль сервера:

```bash
docker compose exec bot python main.py add-group "Название магазина" 123456789
```

Команда скрыто запросит токен сообщества. Затем проверьте метки без вывода текста переписки и токена:

```bash
docker compose exec bot python main.py probe 123456789 --limit 10
```

После сравнения с интерфейсом VK отправьте боту `/sync`. Бот пришлёт результат; `/report` и `/group ID` покажут данные повторно. До добавления первого сообщества бот работает, но статистика будет пустой.

## Google-таблица

Создайте таблицу и поделитесь ею с адресом `client_email` сервисного аккаунта Google как с редактором. JSON-ключ сервисного аккаунта поместите в `secrets/google-service-account.json`; ID таблицы укажите в `.env` как `GOOGLE_SPREADSHEET_ID`. Бот создаст вкладки «Сводка» и «По дням» в этой таблице. Перезапустите контейнер после изменения `.env`.

## Локальные проверки

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

Для ручного отчёта без Telegram: `.venv/bin/python main.py report --days 30`. Для обработки без бота: `.venv/bin/python main.py sync --days 30`.
